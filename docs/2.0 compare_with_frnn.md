# Task 2.0 Compare with FRNN

I'd like you to install the original FRNN package:
```bash
mkdir third_party
cd third_party
 git clone https://github.com/asnaylor/prefix_sum.git \
    && git clone https://github.com/xju2/FRNN.git \
	&& cd prefix_sum \
	&& NVCC_FLAGS="--std=c++17" \
		python setup.py install \
    && cd ../FRNN \
    && NVCC_FLAGS="--std=c++17" \
		python setup.py install
```

## Result

The standalone package is installed as `frnn_cuda`; the original PyTorch
package remains `frnn`. Both import in the same Python environment. The local
`third_party/prefix_sum` build was installed before `third_party/FRNN`:

```bash
export CUDA_HOME="$PWD/.venv/lib/python3.11/site-packages/nvidia/cu13"
export CUDACXX="$CUDA_HOME/bin/nvcc"
export PATH="$CUDA_HOME/bin:$PATH"
export TORCH_CUDA_ARCH_LIST=7.5
export NVCC_FLAGS="--std=c++17"

uv pip install --python .venv/bin/python --no-build-isolation \
  ./third_party/prefix_sum
uv pip install --python .venv/bin/python --no-build-isolation \
  ./third_party/FRNN
```

## Comparison

Run the reproducible comparison with:

```bash
.venv/bin/python tests/compare_frnn_packages.py
```

Measurements on an RTX 2070 SUPER use seeded uniform 3D points, radius chosen
for eight expected neighbors, `max_neighbors=32`, five timed iterations, and
the median latency:

| Points | Directed edges | Edge agreement | `frnn_cuda` host ms | `frnn` GPU ms | `frnn` host ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10,000 | 74,764 | 100% | 1.200 | 1.071 | 1.406 |
| 100,000 | 774,610 | checked at 10k | 14.289 | 1.849 | 4.368 |

`frnn_cuda` host timing is its public synchronous NumPy API, including input
and compact edge-output transfers. `frnn` GPU timing keeps the input and padded
neighbor indices on the GPU. Its host timing additionally copies NumPy input
to CUDA and padded indices back to the CPU. The output representations differ,
so the GPU column is an intentional best-case PyTorch comparison rather than
an identical boundary-cost comparison.

At 10k points, the edge sets match exactly and `frnn_cuda` is slightly faster
than the original host round trip. At 100k points, the original is about 3.3x
faster including its host round trip and 7.7x faster with tensors kept on the
GPU. The current `frnn_cuda` Python binding is therefore attractive when a
small NumPy-only dependency surface and compact edges matter; original FRNN is
better for large PyTorch-resident workloads.

| Capability | `frnn_cuda` | Original `frnn` |
| --- | --- | --- |
| Python dependency | NumPy | PyTorch and `prefix_sum` |
| Python input/output | NumPy points / compact edge list | Batched CUDA tensors / padded distances and indices |
| Autograd | No | Distance gradients |
| Native use | C++/CUDA host, device, and async APIs | PyTorch CUDA extension |
| Same-set output | Directed or unique undirected, optional self exclusion | Directed per-query neighbors, including self unless filtered |
